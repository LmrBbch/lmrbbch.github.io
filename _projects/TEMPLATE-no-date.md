# ============================================================
# 项目技术细节的 front matter
# ------------------------------------------------------------
# 一个项目的每个部分一篇文章。同一个项目的多篇靠 `project` 这个英文 slug
# 聚合成一组，列表页会把它们归到同一个标题下、按 `order` 排好顺序。
# 复制本文件后：改掉 project / project_name / order / section / tags，
# 并删掉下面标了「复制后删除」的那一行。
# ============================================================
layout: page

# 本页大标题，也就是文章里那个 H1。列表页上显示的名字用的是 section，
# 不是这个字段，所以这里写成「项目名 · 章节名」方便自己认就好。
title: "模板 · 项目单篇"

# 【复制后删除】published: false 表示「不发布」。
# 它有两个作用：一是不出现在列表页和统计数字里，二是 Jekyll 仍然会为它
# 生成一个页面（collection 文档即使没有日期也会渲染），所以别指望靠文件名
# 隐藏它。
# 你新建章节时一定要删掉这一行，否则新文章不会出现在 /projects/ 列表页上。
published: false

# 【同一个项目下必须完全一致】项目的英文 slug，只用来做分组，不会显示在页面上。
# 例如线上网关项目就填 gateway。它决定哪些文章会被归到同一个项目标题下——
# 拼错一个字母，那篇文章就会自己单独成一组，或者跑进别的项目里。
# 定了之后尽量别改，改了等于把它挪到另一个分组。
project: TEMPLATE

# 列表页上的项目标题，中文，随时可改。
# 同一个项目下每篇文章都写一遍，列表页取该组第一篇的这个值当标题；
# 如果哪天不一致，以 `order` 最小的那篇为准。
project_name: 模板

# 项目内的阅读顺序，整数，从 1 开始。列表页按它升序排。
# 同一个项目下不要重复，重复了顺序不稳定。
order: 1

# 这一篇讲的是哪一块，列表页上显示为链接文字。
# 这是读者唯一能看到的本章标识，写具体点，别用「第一部分」这种。
section: 模板

# 标签，显示在链接后面。用中括号包起来，逗号分隔。
# C++ 这种带加号的写法可以直接写，YAML 里不需要引号。
tags: [架构, C++]

> 用法：复制一份改名为 `<项目slug>-<章节slug>.md`，例如 `myproject-overview.md`，
> 然后改掉上面的 `project` / `project_name` / `order` / `section` / `tags`，
> 并**删掉 `published: false` 那一行**。
>
> 别忘了删 `published: false`——留着的话你自己的文章不会出现在列表页上。
> 文件名不要带日期前缀，否则 URL 里会带上日期。
